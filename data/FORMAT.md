# Формат `input_trace.csv`

Трасса вводов 4 игроков на 10 000 тиков (60 Гц, ≈ 2 мин 47 с) с моментами доставки на сервер.
Сгенерирована детерминированно: `python3 -I generate_trace.py` (seed `20261009`),
проверка совпадения: `python3 -I generate_trace.py --check`.
Генератор можно использовать для своих трасс (`--seed`, `--ticks`, `--out`).

## Колонки

| Колонка | Тип | Описание |
|---|---|---|
| `tick` | int | тик симуляции, к которому относится ввод (0..9999) |
| `player` | int | id игрока 0..3 |
| `buttons` | int | битовая маска: Up=1, Down=2, Left=4, Right=8, Dash=16 (как `spec::Button`) |
| `send_us` | int | момент отправки клиентом, мкс, на шкале времени сервера: `tick * 16667` |
| `delay_us` | int | односторонняя сетевая задержка этого пакета, мкс |
| `arrival_us` | int | `send_us + delay_us` — момент прихода на сервер |
| `arrival_tick` | int | первый серверный тик `T`, для которого `T * 16667 >= arrival_us`: с этого тика ввод доступен серверу |

Ровно одна строка на пару (`tick`, `player`); строки отсортированы по `tick`, затем по `player`.
Порядок **прихода** на сервер — сортировка по `arrival_us` (`Trace::by_arrival()`).

## Модель сети и упрощения

* Часы клиентов выровнены с сеткой тиков сервера (упрощение): ввод для тика `t` отправляется в `t * TICK`.
* Потерь нет: считаем, что клиент шлёт вводы с избыточностью и каждый ввод рано или поздно доходит.
* Пакеты одного игрока **могут переупорядочиваться** (ввод для `t+1` может прийти раньше ввода для `t`).
* Профили задержки игроков (одинаковы для всего файла):

| Игрок | Профиль | Задержка p50 / p95 / p99, мс | Отставание в тиках (`arrival_tick − tick`), среднее / макс | Смен ввода за тик |
|---|---|---|---|---|
| 0 | `lan` | 8.0 / 10.5 / 11.5 | 1.0 / 1 | 0.024 |
| 1 | `wan_good` | 24.0 / 30.5 / 33.4 | 2.0 / 5 | 0.038 |
| 2 | `wan_jitter` (+ редкие всплески) | 38.3 / 57.8 / 74.2 | 2.8 / 10 | 0.017 |
| 3 | **`lagging`** (+ серии деградации на 30–120 тиков) | 88.5 / 239.3 / 273.4 | 6.7 / 22 | 0.040 |

Игрок 3 — самый «задерживающий» в ≈ 97% тиков; игрок 2 иногда обгоняет его во время всплесков.
Предсказывать нужно **любой** недостающий ввод (а не только ввод игрока 3).

## Поведение ввода

Каждый игрок удерживает «намерение движения» (одно из 9 направлений, включая «стоять») в течение
случайного числа тиков (лог-нормальное распределение, медиана 25–60 тиков в зависимости от игрока),
иногда нажимает Dash на 2–5 тиков. Поэтому предсказание «повтор последнего ввода» в большинстве тиков
верно, но ошибается на каждой смене намерения — именно там и возникают откаты.
